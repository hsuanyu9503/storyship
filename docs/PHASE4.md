## 1. 架構決定：05、07 的投影資料由伺服器產生

Phase 1～3 的投影內容由教師端組好後交給 `teacher_set_stage` 保存。05、07 要展示學生成果，
因此改為**教師只送出「選擇」，伺服器依白名單產生投影資料**：

```
教師端（選擇＝ctl）
   │ teacher_preview_compare / teacher_preview_match（唯讀）──► app.compare_build / app.match_build ──► 預覽
   │ teacher_publish_compare / teacher_publish_match（版本檢查）──► 同一個函式 ──► session_state.projection
   │                                                                       └► session_state.stage_ctl（保存選擇）
投影端 ── projector_state ──► 只讀 session_state.projection（與 Phase 1 相同）
```

* **預覽＝公開**：兩者呼叫同一個 SQL 函式，預覽只是不寫入。
* **白名單**：投影資料只有組別、分類顯示名稱、故事名稱與圖片、教師已揭露的理由／要素；**不含任何 ID、未揭露的文字、教師補充資料**。
* `teacher_set_stage` 拒絕前端自組的 `compare`／`match` 畫面（`BAD_DATA`），避免繞過驗證。
* 返回 05／07 時，伺服器依 `stage_ctl` 中**綁定的 snapshot ID** 重建上次公開的畫面（不靠教師瀏覽器，也不改抓最新快照）。

## 2. 私下預覽與公開分離（教師端）

| 區塊 | 顯示 |
|---|---|
| 右側「● 投影中」 | 伺服器的公開狀態（`projector_state`，與投影端同一份資料） |
| 右側「○ 預覽」 | 目前選擇的預覽；有未公開的變更時標示「僅教師可見，尚未公開」 |
| 控制面板狀態列 | 「尚未公開任何內容」／「預覽中，有尚未公開的變更」／「投影與預覽一致」，以及「公開到投影」「放棄變更」 |

* 選組、選故事、揭露理由、翻頁、選類型、揭露要素都只改變預覽；按「公開到投影」才寫入伺服器。
* 公開失敗（版本衝突、驗證錯誤、網路）時顯示錯誤並保留預覽，**不會被標成已公開**。
* **兩台教師裝置**：公開帶 `session_state.rev`；過期請求回 `STALE`，不覆蓋較新的公開內容，被拒絕的裝置保留自己的預覽。
* **快速連續操作**：同一台裝置一次只送一個公開請求；期間再按公開，會在前一個完成後以**最新的選擇**再送一次。
* **回應反序**：預覽請求帶序號，較舊的預覽回應晚到時忽略；公開狀態只來自伺服器（版本遞增），投影不會倒退。
* 重新整理或換裝置：教師端的選擇從 `stage_ctl` 還原，投影端從 `projector_state` 還原。

## 3. 05｜分類成果大公開

**教師端**

* 依實際組數列出各組：「小組正式提交」「教師結束時保存（未正式提交）」「沒有可展示的成果」（沒有快照，或快照中沒有已分類的故事）。
* 「私下查看」：只在本機開啟該組成果（含所有理由），不會投影。
* 「放左側」「放右側」：選兩個不同小組；同一組不能放在兩側（前端提示，伺服器也以 `SAME_GROUP` 拒絕）。只選一組時單組展示；都不選時投影顯示等待文字，不產生假成果。
* 追蹤故事：選一張故事，兩側標示它所在的分類；不在任何分類時顯示「尚未分類」。只改變展示標示，不移動故事。
* 理由：每一側逐一勾選揭露，或「全部揭露」「全部收合」；預設全部不公開。
* 長內容：每側每頁 4 個分類，由教師翻頁；或「聚焦」單一分類放大顯示。不自動輪播、不縮成小字。
* 同一組有多份快照時：預設最新；可從下拉選單改選較早版本（顯示提交／保存狀態與時間）。

**投影端**（16:9 雙欄，單組時置中單欄）

每側：組別、提交狀態、（追蹤時）該故事的位置、分類名稱（未命名者顯示「分類 N（未命名）」）、分類內故事、
共同特色（未揭露時顯示「共同特色：等一下揭曉」，API 中沒有內容）、未分類故事數量。不顯示對錯、分數、排名或標準答案。

## 4. 成果來源與快照

* 05、07 **只讀 `group_snapshots`**，不讀仍可變動的 `group_categories`／`group_placements`。
* 每次預覽與公開都綁定 snapshot ID；輪詢不會改抓最新快照。
* 快照排序：`created_at` 由新到舊，時間相同時以 id 排序（穩定）。
* 已綁定的快照之後若出現較新的快照（例如返回 04 重新開放、再次提交），教師端顯示「這一組有較新的成果」，
  按「改用新版本（預覽）」再公開才會更換；**已公開的畫面不會自己改變**（db 測試驗證）。
* **舊格式相容**：`app.snapshot_norm` 同時讀取 Phase 3 格式（含 `order`、`cards`）與 Phase 1／2 格式（只有 `categories`＋`placements`），
  一律以 `placements` 決定歸屬、只顯示有故事的分類。不重寫任何既有快照。
* 展示、追蹤、揭露、對照都只讀取，**不修改**個人資料、小組資料或快照（db 測試以雜湊逐份比對）。

## 5. 06｜揭開小說類型

既有流程（回顧人物、情節、背景 → 逐一揭露類型與三個要素 → 總覽；教師私下預覽不投影）保留不變。補上的缺口：

* **揭露紀錄跨環節保存**：原本已揭露的類型只存在目前的投影內容與教師瀏覽器。現在 `teacher_set_stage` 會把 06 公開的類型
  加入 `session_state.disclosure.genres`（只增加；索引必須是本場素材中存在的類型）。換裝置、重新整理、從 07 返回 06 都會保留。
* 在 07 公開的類型也加入揭露紀錄，返回 06 時總覽會顯示。
* 進入 07 **不會**公開全部類型。

## 6. 07｜小小故事分類師

**教師端**：① 選小組與快照（可選較早版本）→ 選一個分類（可一併顯示它的共同特色）；② 選小說類型（可不選；06／07 公開過的標 ✓）；
③ 逐一揭露該類型的三個核心要素、勾選「標示相似」（只能標示已揭露的要素）；顯示／隱藏句型鷹架；「清除對照」。

* 更換類型時清除要素揭露與相似標示（前端與伺服器都檢查：標示必須是已揭露的要素）。
* 收回某個要素時，一併取消它的相似標示。
* 不自動配對、不評分、不計算符合率、不改名。

**投影端**：左側分類（組別、名稱、故事圖片與名稱）；右側類型名稱、主視覺、三個要素位置（未揭露的只顯示「？ 核心要素」，API 中沒有標籤）；
底部句型鷹架「我們把這些故事分在一起，是因為＿＿＿＿，這些特色和＿＿＿＿小說比較接近。」

## 7. 資料安全與權限

| 項目 | 做法 |
|---|---|
| 教師身分 | 預覽：`app.teacher_session_ro`（白名單＋場次擁有者，只讀不鎖）；公開：`app.own_session`（沿用 Phase 3 的 `FOR NO KEY UPDATE`）＋`session_state FOR UPDATE` |
| 選擇驗證 | snapshot 必須屬於該場次；兩側不能同組；揭露／聚焦的分類必須屬於該側快照；故事必須屬於本場素材；頁數、類型、要素索引範圍；要素不重複；標示⊆揭露；不合法 ID → `BAD_DATA` |
| 學生／投影 | anon 不能執行任何 `teacher_*` 函式，也不能讀 `group_snapshots`、`session_state` |
| 其他教師 | `FORBIDDEN`；RLS 讀不到 `stage_ctl` |
| 文字呈現 | 學生輸入的名稱與理由一律以文字節點插入（`createTextNode`），不使用 innerHTML |
| 鎖定順序 | 新函式沿用 sessions → session_state 的取得順序；只讀快照，不碰 groups 列 |

## 10. 已知限制與尚待驗證

* **只在本機驗證**：PostgreSQL 16＋模擬 Supabase API（`tests/e2e/shim.js`，不提供 Realtime）＋ headless Chromium。
  **尚未在正式 Supabase 驗證**：PostgREST 實際行為、雙教師 JWT 負面測試、預設 ACL、Realtime。
* **尚未實機驗證**：教師平板觸控操作、教室投影機的實際可讀性（16:9 版面以 1600×900 截圖檢查）。
* 每側每頁固定 4 個分類；分類內故事很多（例如 8 張）時以換行呈現，仍需在實際投影確認字級。
* 投影的故事圖片沿用素材的 `image_url`；目前為佔位框。
* Phase 3 複檢列出的 D2（跨鎖逾時的真實並行讀取）仍未以真實並行重現。
* 結束 03 時班上沒有學生等 Phase 3 已記錄的限制不變。
