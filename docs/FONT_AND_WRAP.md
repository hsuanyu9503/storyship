# 全螢幕返回、中文換行與標楷體（2026-11）

**已決定（2026-11-15）：全站改用標楷體。** 標楷體沒有粗體（由瀏覽器模擬）可接受；沒有標楷體的裝置（例如 iPad）改用其他楷書字型或黑體、各裝置字體不完全一致，可接受。
套用方式見第 3 節「正式套用」。下面第 3 節其餘內容是試排當時的紀錄。

## 1. 學生退出全螢幕時的「回到全螢幕」

* 檔案：`js/student/fullscreen.js`（新增）、`js/student/main.js`（「進入探索模式」改呼叫 `enterFullscreen`）、`css/app.css`（`.fsr-*`）。
* 依瀏覽器實際狀態（`document.fullscreenElement`／`webkitFullscreenElement`、`fullscreenchange`）判斷。學生按過「進入探索模式」後，
  只要不在全螢幕，就在目前畫面上方顯示「請回到全螢幕，繼續活動」與大按鈕「回到全螢幕」（220×56px）；回到全螢幕後消失，再次退出再出現。
* 提示是獨立的浮層，不重畫下面的畫面：作答、分組、卡片位置、閱讀卡的翻面狀態都保留，也不重新整理或重新加入。
  閱讀卡（強制回應對話框）開著時，提示放進對話框裡（否則被對話框擋住、不能點）。提示出現時不搶走焦點（學生可能正在輸入）。
* 觸控、滑鼠、鍵盤（Tab 到按鈕後 Enter／空白鍵）都能操作。
* 瀏覽器拒絕：顯示「瀏覽器沒有允許全螢幕。可以再試一次，或先繼續活動。」與「再試一次」「繼續活動」；
  裝置不支援（例如 iPhone 的 Safari）：顯示「這台裝置或瀏覽器不支援全螢幕，請直接繼續活動。」與「繼續活動」。按「繼續活動」後收起，活動照常。
* 只套用在學生端。教師端、投影端不變。

## 2. 中文換行（現行字體先修正，再用標楷體複查）

| 問題 | 處理 |
|---|---|
| 段落末行只剩一個字（例如開場語末行「想？」、柯南線索「樣。」「險。」、《國家寶藏》「面！」、《寶可夢》「戰。」、窄螢幕《鬼滅之刃》「鬼。」、學生提示「論。」） | 段落加 `text-wrap: pretty`（依寬度自動調整，不寫死斷點） |
| 短標題、按鈕、提問句兩行時分配不均 | `text-wrap: balance` |
| 按鈕在詞中間斷開（例如「下一環／節」） | 短的介面文字（按鈕、標題、狀態列）`word-break: keep-all`＋`overflow-wrap: anywhere`：只在標點與空白處換行，真的放不下才任意斷行 |
| 按鈕結尾的「→」單獨一行 | 文字與箭頭之間改用不換行空白（教師端所有「… →」「← …」按鈕） |
| 名字變化（甲 → 乙） | 兩個姓名各自不拆開，箭頭與新名字放在一起：換行時是「工藤新一」／「→ 江戶川柯南」，不會只剩箭頭 |
| 教師端「投影目前：…已顯示 0 / 3 條線索」在窄螢幕末行只剩「索」 | 數字與「條線索」之間用不換行空白，換行點落在「：」 |
| 平板寬度（761～1180px）環節列表的名稱被切成「走進故／事世界」 | 該寬度的左欄由 180px 改為 200px，並隱藏建議分鐘數；環節名稱維持逐字換行＋balance |

沒有改動原稿用字與標點；投影字級、故事卡翻面效果不變。

`orphan`（末行一字）、`punct`（行首標點）、`names`（姓名拆開或箭頭單獨一行）屬於斷行；`clip`（超出會裁切的容器、投影畫面或視窗，可捲動的區域不算）屬於截掉。

## 3. 標楷體

### 正式套用（2026-11-15）

* `css/app.css`：`:root` 定義 `--kai` 字型順序並設為全站字體（教師端、學生端、投影端、閱讀卡、輸入框）。作品編號（Georgia）與活動代碼（等寬字）維持原字型。
* 試排開關（`js/lib/font-preview.js`、`?font=kai`、右下角「標楷體試排」標籤）已移除；不需要任何網址參數。舊的 `?font=` 參數與瀏覽器裡留下的試排紀錄不再有作用。
* 本機對照頁 `font-compare.html` 保留：左邊改版前字體（`font-fixture.html?font=old`）、右邊標楷體，不會發布。
* 換行檢查（`wrap_audit.js`，預設即標楷體；`FONT=old` 為改版前字體）：兩種字體都是末行一字 0、行首標點 0、姓名拆開 0、裁切 0。
* 仍待在 Windows 上實際看一次真正的標楷體（本環境只能用 AR PL UKai TW 代替）。

### 試排時的預覽方式（已移除，僅留紀錄）

* **任何頁面**：網址加上 `?font=kai`（例如 `teacher.html?font=kai`、`join.html?font=kai`、投影網址後加 `&font=kai`），
  這台裝置的教師端、學生端、投影端都改用標楷體，記在這台瀏覽器（換頁仍有效）；加 `?font=default` 取消。右下角會顯示「標楷體試排」小標籤。
  不影響資料或其他裝置。
* **同一畫面左右對照（Windows 本機）**：在專案資料夾執行 `python -m http.server 8080`，開啟
  `http://localhost:8080/font-compare.html`。可選畫面（千尋的三條線索、名字比較、公布千尋、《動物方城市》故事卡背面、教師端 01 按鈕）
  與尺寸（1920×1080、1366×768、1024×768、768×1024、390×844），左邊現行字體、右邊標楷體。
  `font-compare.html`、`font-fixture.html` 只在本機使用，不會發布到網站（`tools/build_site.sh` 不包含）。
* 字型順序：`標楷體`（DFKai-SB，Windows 內建）→ BiauKai → TW-Kai → Kaiti TC → STKaiti → AR PL UKai TW … → 現行字體。
  作品編號（Georgia）與活動代碼（等寬字）維持原字型。

### 本次截圖的實際字型（重要）

這個開發環境沒有標楷體，也沒有現行字體清單中的 Noto Sans TC、PingFang TC、Microsoft JhengHei：

* 「現行字體」實際顯示為 **WenQuanYi Zen Hei**（文泉驛正黑；英文與箭頭為 Inter），不是 Windows 上的微軟正黑體。
* 「標楷體」實際顯示為 **AR PL UKai TW**（文鼎 PL 中楷，開放授權），不是 Windows 的標楷體（DFKai-SB）。

（以 Chrome DevTools Protocol 的 `CSS.getPlatformFontsForNode` 逐張確認，見每張對照圖上方的「實際字型」。）
因此對照圖只能代表「楷書」的大致效果（寬度、筆畫粗細、換行），**字形細節請以 Windows 本機的 font-compare.html 為準**。

### 待你決定

1. 是否全站改用標楷體，或只用在部分畫面（例如投影的作品名稱與標題，內文與按鈕維持現行字體）。
2. 投影線索與故事卡內文在標楷體下沒有粗體（瀏覽器可能以模擬粗體顯示，效果因系統而異），是否接受，或改以字級／顏色加強。
3. 在 Windows 本機用 `font-compare.html` 確認標楷體字形與後排可讀性（本次沒有真正的標楷體截圖）。
4. iPad（Safari）沒有標楷體，會改用 Kaiti TC（若有）或回到現行字體，各裝置字體可能不一致。
