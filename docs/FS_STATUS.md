# 教師端查看學生全螢幕狀態（2026-11-26）

延伸 [`SEAT_FULLSCREEN.md`](SEAT_FULLSCREEN.md)，那份文件說明座號、確認加入後進入全螢幕、全黑遮罩。

教師端顯示的是**學生裝置回報的狀態**，提示用語只說「已退出全螢幕」，不推定原因。

## 1. 學生端偵測與回報

* 重用 `js/student/fullscreen.js` 的判斷：只看瀏覽器實際狀態（`fullscreenElement`、`fullscreenchange`）。
  * 虛擬鍵盤、視窗大小改變、輸入框取得焦點，都不會單獨被當成退出。
  * 退出時仍顯示原本的黑底提示與「回到全螢幕」；打字中延後遮罩、完成輸入自動返回的行為都不變。
* 回報的值：`on`（全螢幕中）、`off`（不在全螢幕）、`typing`（打字中不在全螢幕：焦點在文字欄位、遮罩延後中，或完成輸入時正在自動重新進入）、`denied`（請求未被允許）、`unsupported`（裝置不支援）。
  * 「已退出」或「尚未進入」由伺服器依「這次加入後是否曾進入全螢幕」判斷。
* 什麼時候回報：
  * 狀態改變時（加入時進入、成功進入、退出、重新進入、請求被拒絕）。
  * 加入或重新整理後。
  * 斷線後重新連線時、回到前景時：先以當下狀態重新回報。
* 順序與重送（`js/student/fs-report.js`）：
  * 每次回報帶遞增序號，取「現在毫秒」與「本機上一個序號＋1」中較大者。序號記在本機，重新整理後仍會遞增。
  * 伺服器只接受比目前更大的序號，所以重送、延遲送達、順序顛倒的「已退出」不會蓋過較新的「全螢幕中」。
  * 只保留最新要回報的狀態。送出中又改變時，送完後只再送最新的。
  * 失敗時以 1、2、4…最多 15 秒重試。
  * 本機序號紀錄遺失、伺服器序號較大時，採用伺服器序號後重新回報。
* 回報成功後送出既有的 Realtime 通知（`sync.ping`），教師端立即重新讀取。Realtime 不可用時，教師端每 3 秒輪詢一次。

## 2. 資料與權限

* 保存在 `participants`（學生紀錄）新增的欄位：
  * `fs_state`：active／exited／none／denied／unsupported；null 表示尚未回報。
  * `fs_seq`：已接受的最大序號。
  * `fs_at`：伺服器接受最後一次回報的時間。
  * `fs_ever`：這次加入後是否曾進入全螢幕。
  * `fs_exits`：要提醒教師的退出次數，只增不減。
  * `fs_typing`：最後一次的「已退出」發生在打字中（尚未提醒）。
* 回報**不推進** `session_state.rev`，不鎖課程狀態，不碰分類資料與版本，所以不干擾作答保存，也不增加操作衝突。只更新該學生自己的一列（同時更新在線時間）。
* `student_report_fullscreen(p_session, p_token, p_state, p_seq)`（security definer）：
  * 裝置憑證必須屬於該場次（否則 `NOT_JOINED`）。
  * 學生必須目前在組內、場次進行中，否則不更新（`INACTIVE`）。
  * 狀態值或序號不合法時回傳 `BAD_DATA`。
* 權限：
  * 學生（anon）不能直接讀寫 `participants`。
  * 教師只能讀取自己場次的 `fs_state`、`fs_at`、`fs_ever`、`fs_exits`（RLS＋欄位授權），不能改寫。
  * 檢查項目在 `verify.sql` 第 19 項、`tests/db/tests.sql`、`tests/e2e/fs_status.js`。
* 被移出後重新加入時，全螢幕狀態重新開始。序號與退出次數保留（只增不減），教師端不會把舊事件當成新的。

## 3. 教師端顯示（`js/lib/fs-status.js`）

在每位學生的座號旁，用顏色加文字顯示：

| 狀態 | 顏色 | 文字 |
|---|---|---|
| 全螢幕中 | 綠 | 全螢幕中 |
| 曾進入後退出（含重新整理、斷線期間退出） | 紅 | 已退出全螢幕 |
| 加入後尚未進入過 | 灰 | 尚未進入全螢幕 |
| 尚未進入過且請求未被允許 | 灰 | 尚未進入全螢幕（瀏覽器未允許） |
| 裝置不支援 | 灰（米色底） | 裝置不支援全螢幕 |
| 超過在線時間 | 灰（虛線框） | 連線中斷／狀態待確認 |
| 舊版前端或剛升級、尚未回報 | 灰 | 狀態待確認（尚未回報） |

* 顯示位置：
  * 連線管理（每位成員，含「更新 HH:MM:SS」或「最後回報 HH:MM:SS」）
  * 03 個人分類成員表（新增「全螢幕」欄，含時間）
  * 02 各組加入狀態、04 小組進度（精簡清單，滑鼠停留顯示最後回報時間）
* 名稱沿用 `seatText`：有座號顯示「12 號」；舊資料顯示「未填座號（組內第 N 位）」。
* **過期判定**：不新增時間門檻，**沿用連線管理既有的在線判定（最後連線 40 秒內）**。
  * 理由：學生裝置在線時，狀態一改變就會回報，失敗會重試，重連後也會重送，所以在線期間最後一次回報仍有效。
  * 超過在線時間（斷線、關閉頁面、平板休眠）就改成灰色「連線中斷／狀態待確認」，不會一直顯示綠色。
  * 代價：學生關閉頁面後，最多約 40 秒仍顯示關閉前的狀態。

## 4. 退出提醒

* **打字中的退出不提醒（2026-11-26 決定）**：
  * iPad 打字時系統會退出全螢幕。這時學生端回報 `typing`，教師端照樣顯示紅色「已退出全螢幕」，但不跳提醒。
  * 完成輸入自動回到全螢幕後恢復綠色，整段都不提醒。
  * 如果打字中退出後，學生離開文字欄位仍不在全螢幕（例如系統收起鍵盤，學生端出現黑底提示），學生端會改回報 `off`，這時才提醒教師一次，避免學生停在全螢幕外卻沒有提醒。
* 教師端讀到 `fs_exits` 比上次看到的大，表示有新的、要提醒的退出（從全螢幕中退出，或打字中退出後離開欄位仍不在全螢幕），就在左下角顯示提醒，例如「第 3 組・12 號退出全螢幕」。
  * 提醒不接收點擊、不是對話框、不搶焦點、沒有音效，6 秒後自動消失。
* 同一次退出只提醒一次：
  * 教師端開啟或重新整理時，只記錄當下的次數作為基準，不提醒歷史事件。
  * 輪詢、重送、重連重新讀取時，次數沒變就不提醒。
* 多位學生短時間退出（約 0.8 秒內，或提醒還在顯示時）會彙整成一則，例如「3 位學生退出全螢幕：第 1 組・7 號、第 3 組・21 號、第 4 組・30 號」，超過四位顯示「等」。
* 學生已經返回才被教師端讀到時，標示「（已返回）」。
* 返回全螢幕不提醒，清單自動恢復綠色。

## 5. 資料庫升級步驟（由管理者執行）

1. **先升級資料庫，再更新網站。** 在 Supabase SQL Editor 執行 `supabase/upgrade/upgrade.sql`（單一交易、可重複執行），結果 **19 列**都應為 `true`。第 19 項檢查：
   * 全螢幕欄位（6 個）與檢查存在
   * 回報函式學生可執行
   * 教師可讀不可改
   * 學生不能直接讀寫
2. 網站合併並部署後，所有裝置重新整理。
3. 相容性：
   * 舊版網站與新資料庫相容：舊版不回報，教師端也不讀新欄位。
   * 新版教師端在資料庫尚未升級時會退回讀舊欄位，全螢幕狀態一律顯示「狀態待確認（尚未回報）」。
   * 新版學生端在資料庫尚未升級時，回報會失敗並重試，不影響作答。

## 6. 測試

全部是瀏覽器模擬，**沒有實體裝置測試**。環境是 Linux 容器裡的 Playwright Chromium 153（headless）；學生 1024×768（觸控模擬），教師 1366×1024。

* `tests/e2e/fs_status.js`（66 項），從正常教師入口（登入、建立場次）與學生入口（座號 → 組別 → 確認加入）操作：
  * 加入並進入全螢幕：教師端組別、座號正確，綠色，有更新時間；回報不推進課程版本。
  * 手動退出：學生端黑底提示；教師端紅色、提醒一次（不擋點擊）；返回後綠色；多次輪詢後仍只提醒一次。
  * 打字、注音組字與選字、可視區域縮小：沒有送出任何狀態變更。
  * 打字中裝置確實退出（模擬 iPad）：如實顯示已退出，**不跳提醒**；完成輸入自動返回後恢復綠色，也不提醒。
  * 打字中退出後沒有回到全螢幕就離開欄位：學生端黑底提示，這時提醒教師一次。
  * 重複、延遲、順序顛倒的回報：被忽略，狀態不倒退、不多提醒。本機序號紀錄遺失後仍能正確回報。
  * 斷線：超過在線時間（以把最後連線時間往前調模擬）變成待確認；斷線期間退出，重連後回報並提醒一次。
  * 關閉頁面後變成待確認；重新整理後顯示已退出，返回後綠色。
  * 三位不同組學生同時退出：彙整成一則提醒。教師端重新整理：不重複提醒，對應正確。
  * 請求被拒絕：「尚未進入（瀏覽器未允許）」；從未進入的學生重新整理：「尚未進入」，不提醒。不支援：「裝置不支援全螢幕」。舊資料：「未填座號（組內第 1 位）」＋「狀態待確認（尚未回報）」。
  * 02／03／04 成員清單都顯示狀態。
  * 權限：不能回報其他場次、未加入不能回報、不合法狀態被拒；anon 不能直接讀寫；教師不能直接改寫；其他教師讀不到。
* `tests/db/tests.sql`：全螢幕 37 項（狀態判斷、重送與延遲、退出次數、打字中退出不計入與之後離開欄位的計入、移出後重新加入、權限、不推進版本）。
* `tests/db/upgrade_bundle.sh` 第 12 項：從已部署的 main（`d01b7b3`）加上 04 進行中的場次升級：
  * 資料不變，19 項全過。
  * 既有學生為尚未回報。
  * 可回報，且不推進課程版本。
  * 教師可讀；共作照常。
  * 重複執行不改狀態。
* `tests/unit/fs-status.test.mjs`：回報序號、合併、重試退避、序號遺失、重連；教師端顯示、退出提醒去重、彙整文字。

### 尚未驗證

* 實體平板：iPad（Safari、Chrome）、Android 平板、Chromebook。包括實際的系統手勢退出、虛擬鍵盤、平板休眠與喚醒後的回報。
* 真正的 Supabase Realtime 通知延遲（本機模擬 API 沒有 Realtime，測試走 3 秒輪詢）。
* 多台教師裝置同時開啟時各自提醒（每台各自提醒一次，未另外測試）。
* iPad 實機上「打字中」的判斷（焦點在文字欄位時退出全螢幕）是否與預期一致，尚未在 iPad 上驗證。
